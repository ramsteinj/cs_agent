# 01. 기능 요구 사항

요구 사항 ID 규칙: `F-U*` 고객(사용자), `F-A*` 관리자. 각 항목의 **인수 조건(AC)** 은 테스트로 검증한다.

---

## 고객 (사용자)

### F-U1. 로그인 없는 채팅 문의
- 고객은 로그인 없이 메인 화면(`/`)의 채팅 UI에서 회사/제품에 대해 질문하고 답변을 받는다.
- 답변은 관리자가 등록한 회사/제품 정보에 근거해야 한다. 근거가 없으면 모른다고 답하고 추측하지 않는다.
- 같은 브라우저 탭 세션 안에서는 이전 대화 맥락을 유지한다 (최근 N턴, specs/05 참조).
- 답변은 스트리밍으로 점진 표시한다.

**AC**
- [ ] 비로그인 상태에서 질문 전송 시 답변이 표시된다.
- [ ] 등록된 제품명을 물으면 해당 제품 설명에 근거한 답변이 나온다.
- [ ] 등록되지 않은 내용을 물으면 "확인할 수 없다"는 취지의 답변과 함께 문의 채널(회사 연락처가 등록되어 있다면)을 안내한다.
- [ ] 후속 질문("그거 가격은?")이 직전 대화 맥락으로 해석된다.

### F-U2. API Key 미등록 시 채팅 비활성화
- 관리자가 선택한 LLM 공급자의 API Key나 모델이 설정되지 않은 경우 채팅 입력창과 전송 버튼을 `disabled` 처리한다.
- 비활성 상태에서는 "현재 상담 서비스를 준비 중입니다." 안내 문구를 채팅 영역에 표시한다.
- 프론트엔드는 페이지 진입 시 `GET /api/chat/status`로 상태를 확인한다.
- 백엔드도 키가 없으면 채팅 API 요청을 `503 CHATBOT_DISABLED`로 거부한다 (프론트 우회 방지).

**AC**
- [ ] API Key가 없을 때 입력창/버튼이 disabled이고 안내 문구가 보인다.
- [ ] API Key가 없을 때 `POST /api/chat/messages` 호출 시 503과 `CHATBOT_DISABLED` 코드가 반환된다.
- [ ] 관리자가 키를 등록한 뒤 고객 화면을 새로고침하면 채팅이 활성화된다.

### F-U3. 대화 초기화
- "새 대화" 버튼으로 현재 대화를 지우고 새 세션을 시작한다.

### F-U4. 오류 처리
- Claude API 오류, 네트워크 오류, 시간 초과 시 "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해 주세요." 를 표시하고 재시도할 수 있다.
- 응답 생성 중에는 전송 버튼을 비활성화하고 로딩 표시를 한다.

### F-U5. 입력 제한
- 메시지 최대 1,000자. 빈 메시지 전송 불가. Enter 전송, Shift+Enter 줄바꿈.

## 관리자

### F-A1. 로그인 / 로그아웃
- 화면 **상단 우측**에 "관리자 로그인" 버튼을 둔다. 클릭 시 ID/비밀번호 입력 모달.
- 로그인 성공 시 상단 우측에 관리자 ID와 "관리자 페이지", "로그아웃" 메뉴를 표시한다.
- 로그인 실패 시 "아이디 또는 비밀번호가 올바르지 않습니다." (어느 쪽이 틀렸는지 구분하지 않음)
- `role == ADMIN` 인 사용자만 관리자 로그인 가능. 그 외 계정은 동일한 실패 메시지.
- 연속 5회 실패 시 해당 ID 5분간 로그인 차단 (specs/07).

**AC**
- [ ] `admin` / `admin1234!` 로 로그인 성공 후 관리자 메뉴가 보인다.
- [ ] 잘못된 비밀번호로 로그인 시 401과 공통 실패 메시지.
- [ ] 로그아웃 후 관리자 API 호출 시 401.
- [ ] 비로그인 상태로 `/admin/*` 경로 진입 시 메인으로 이동하고 로그인 모달이 열린다.

### F-A2. 기본 관리자 계정 자동 생성
- 앱 시작 시(`migrate` 직후 `post_migrate` 시그널 + 서버 시작 스크립트에서 `ensure_default_admin` 커맨드) 관리자 계정이 **하나도 없으면** 다음 계정을 생성한다.
  - ID: `admin`, 비밀번호: `admin1234!`, role: `ADMIN`, `is_staff=True`, `must_change_password=True`
- 이미 `role=ADMIN` 사용자가 하나라도 있으면 아무것도 하지 않는다 (멱등).
- 생성 시 로그에 "Default admin account created" 만 남기고 비밀번호는 남기지 않는다.

**AC**
- [ ] 빈 DB에서 migrate 후 `admin` 계정이 존재하고 비밀번호가 `admin1234!` 로 인증된다.
- [ ] 커맨드를 두 번 실행해도 계정이 중복 생성되거나 비밀번호가 초기화되지 않는다.

### F-A3. 비밀번호 변경
- 관리자는 관리자 페이지에서 비밀번호를 변경할 수 있다 (현재 비밀번호 확인 필수, Django 비밀번호 정책 적용).
- `must_change_password=True` 인 계정은 로그인 후 관리자 페이지 상단에 "기본 비밀번호를 변경하세요" 경고 배너를 표시한다. 변경 시 플래그 해제.

### F-A4. 회사 정보 관리 (CRUD)
- 회사 정보 항목: 회사명(필수), 소개(필수), 웹사이트, 대표 연락처(전화), 이메일, 주소, 운영 시간, 기타 안내(FAQ/정책 등 자유 텍스트).
- 목록 / 상세 / 생성 / 수정 / 삭제. 삭제 전 확인 다이얼로그.
- 저장 시 텍스트를 청킹·임베딩하여 pgvector(`KnowledgeChunk`)에 저장. 수정 시 기존 청크 삭제 후 재생성. 삭제 시 청크도 삭제(소속 제품과 그 청크도 함께 삭제됨을 확인 다이얼로그에 명시).

**AC**
- [ ] 회사 생성 후 `KnowledgeChunk`에 `source_type=company` 레코드가 1개 이상 생성된다.
- [ ] 회사 정보 수정 후 챗봇이 수정된 내용으로 답변한다.
- [ ] 필수값 누락 시 400과 필드별 오류 메시지가 화면에 표시된다.

### F-A5. 제품 정보 관리 (CRUD, Text / MS Word / PDF 입력)
- 제품 항목: 소속 회사(필수), 제품명(필수), 카테고리, 요약, 상세 설명, 가격(텍스트, 예: "월 9,900원"), 주요 기능, 사용 방법, FAQ, 판매 여부(활성/비활성).
- 제품 정보 입력 방법:
  - **Text**: 위 항목을 화면에서 직접 입력
  - **파일**: `.txt`, MS Word(`.docx`), PDF 파일을 업로드하면 텍스트를 추출해 제품 정보로 사용 (여러 개 가능, 파일당 10MB 이하)
  - 한 제품에 사용자 매뉴얼, 빠른 설치 가이드 등 여러 문서를 올리고 문서마다 **제목(종류)**을 붙일 수 있다. 업로드 후에도 제목을 바꿀 수 있다.
  - 같은 회사 안에서 **제품명이 같아도 카테고리가 다르면** 별도 제품으로 등록할 수 있다 (제품명·카테고리가 모두 같으면 중복). 이름이 같은 제품은 관리자 목록과 챗봇 출처에 카테고리를 함께 표시해 구분한다.
  - 문서 1개당 추출 텍스트는 최대 1,000,000자. 큰 문서는 업로드에 수십 초가 걸릴 수 있다(1,000,000자 ≈ 2,300청크, CPU 기준 약 40초).
  - 상세 설명 또는 문서 중 하나 이상이 있어야 저장할 수 있다.
- 목록(검색: 제품명, 필터: 회사·카테고리·활성, 페이지네이션 20개) / 상세 / 생성 / 수정 / 삭제. 문서 목록에서 개별 문서를 삭제할 수 있다.
- 저장(필드 수정, 문서 추가·삭제) 시 제품 필드와 문서 텍스트를 청킹·임베딩. **비활성 제품의 청크는 검색에서 제외**한다.

**AC**
- [ ] 제품 생성/수정/삭제 시 해당 청크가 생성/재생성/삭제된다.
- [ ] 비활성 제품에 대해 질문하면 해당 제품 정보가 근거로 사용되지 않는다.
- [ ] PDF/Word/텍스트 파일을 올리면 추출한 텍스트가 제품 청크에 포함되고, 문서에만 있는 내용으로 질문하면 그 내용으로 답한다.
- [ ] 문서를 삭제하면 그 문서의 청크도 사라진다.
- [ ] 문서 제목을 붙이면 청크 헤더와 챗봇 출처에 "제품명 · 문서 제목"으로 표시된다.
- [ ] 지원하지 않는 파일(.doc, 이미지 등), 10MB 초과, 텍스트가 없는 PDF는 명확한 오류 메시지로 거부된다.

### F-A6. LLM 공급자 및 API Key 관리
- LLM은 **ChatGPT(OpenAI), Claude(Anthropic), Gemini(Google)** 중 하나를 관리자 화면에서 선택한다. 선택한 공급자로만 답변을 생성한다.
- 공급자마다 API Key를 관리자 화면에서 입력·저장한다. 저장 전 해당 공급자 API로 키 유효성을 검증한다(무료 모델 목록 조회). 실패 시 저장하지 않고 "유효하지 않은 API Key입니다." 표시.
- 키는 PostgreSQL에 **암호화**하여 저장 (specs/07). 조회 시 마스킹 값(예: `sk-ant-...abcd`)과 등록 일시만 반환.
- 키 삭제 가능. 선택된 공급자의 키를 삭제하면 즉시 챗봇 비활성화. 공급자를 바꿔도 다른 공급자의 키는 유지된다.

**AC**
- [ ] 선택된 공급자의 유효한 키와 모델이 있으면 `GET /api/chat/status` 가 `enabled: true`.
- [ ] 공급자를 키가 없는 공급자로 바꾸면 `enabled: false`.
- [ ] DB의 저장 값이 평문 키와 다르다(암호문).
- [ ] 어떤 API 응답에도 평문 키가 포함되지 않는다.

### F-A7. 모델 및 챗봇 설정
- 공급자별 모델을 선택한다.
  - Claude 기본 모델은 **`claude-opus-5-5`(Opus 5.5)**. 관리자가 `claude-sonnet-5-5`(Sonnet 5.5), `claude-haiku-4-5` 등으로 바꿀 수 있다.
  - ChatGPT·Gemini는 등록한 키로 공급자의 모델 목록을 불러와 그중에서 선택한다.
- 공급자별 **Temperature**를 설정할 수 있다. 비워 두면 모델 기본값을 쓴다. 범위: Claude 0~1, ChatGPT·Gemini 0~2.
  - 선택한 모델이 temperature를 지원하지 않으면 관리자 화면의 temperature 입력을 **비활성화**하고 이유를 표시한다 (예: Claude Opus 5.5 / Sonnet 5.5).
  - 지원하지 않는 모델에는 저장된 값이 있어도 요청에 temperature를 보내지 않는다.
- 챗봇 이름, 환영 메시지, 추가 지시사항(답변 톤 등, 시스템 프롬프트에 덧붙임, 최대 2,000자)을 변경할 수 있다.
- **시스템 프롬프트**를 DB에 저장하고 관리자 화면에서 수정할 수 있다 (최대 10,000자, 비울 수 없음). `{bot_name}`은 챗봇 이름으로 바뀐다. 기본값(specs/05 §4.3)으로 되돌릴 수 있다. 변경은 다음 질문부터 적용된다.

**AC**
- [ ] 새로 설치하면 Claude 모델이 `claude-opus-5-5`로 설정되어 있다.
- [ ] `claude-opus-5-5`를 선택하면 temperature 입력이 비활성화되고, `claude-haiku-4-5`를 선택하면 활성화된다.
- [ ] 지원하지 않는 모델에 temperature를 저장하려 하면 400으로 거부된다.
- [ ] Claude 모델을 `claude-sonnet-5-5`로 바꾸면 다음 답변부터 그 모델로 생성된다.
- [ ] 시스템 프롬프트를 수정하면 다음 질문부터 수정한 프롬프트로 답변하고, "기본값으로 되돌리기"로 원래 문구를 복원할 수 있다.

### F-A8. 지식 재색인
- "전체 재색인" 버튼: 모든 회사/제품(문서 포함)의 청크를 다시 생성. 진행 중 중복 실행 방지.

### F-A9. RAG 튜닝 설정
- RAG 튜닝에 필요한 설정을 모두 PostgreSQL에 저장하고 관리자 화면(**시스템 설정 → RAG 설정**)에서 변경한다: 임베딩 모델, 청크 최대 길이, 청크 겹침, 검색 청크 수(Top-K), 최대 거리, 검색어에 직전 질문 포함 여부, 대화 기록 메시지 수, 출처 표시 개수, 답변 최대 출력 토큰 (값과 범위는 specs/05 §1.1).
- 임베딩 모델·청크 설정을 바꾸면 저장과 함께 전체 재색인한다. 재색인이 실패하면 변경을 취소한다.

**AC**
- [ ] 설정을 바꾸면 서버 재시작 없이 다음 질문부터 적용된다.
- [ ] 청크 길이를 바꾸면 전체 재색인되어 청크가 새 길이로 다시 만들어진다.
- [ ] 범위를 벗어난 값, 차원이 다른 임베딩 모델은 필드 오류로 거부된다.
